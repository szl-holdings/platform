## Token diagnosis

`GH_WORKFLOW_TOKEN` is a **fine-grained PAT** with `metadata=read`
as its only accepted-permissions header — i.e. it can *read* every
public repo and was granted *contents:write* on `platform`
specifically (the file PUTs returned 201). It has **no
contents:write on `ouroboros-thesis` or `lutar-lean`**, and **no
pull-requests:write anywhere** (every `POST /pulls` returned 403
"Resource not accessible by personal access token").

The earlier `permissions: { push: true, admin: true }` we saw via
`GET /repos/:org/:repo` reflects **what the authenticated user owns
on that repo**, not what *the token itself* can do. Lesson learned —
that header is misleading for fine-grained PATs.

**Building in public: 16 apps, one TypeScript monorepo, zero excuses.**

Six months ago I set out to prove a thesis: a single founder can architect enterprise-grade software across multiple verticals — defense, maritime, real estate, legal, consulting, fintech — without a 50-person engineering org.

Today the SZL Holdings platform stands at:

- 10 production web applications (React + Vite)
- 7 native mobile apps (Expo / React Native)
- 1 unified API server (Node.js + PostgreSQL)
- 1 cross-domain mobile command center (CORTEX)
- Shared libraries: PRISM event bus, Forge runtime, design tokens

The stack:
TypeScript everywhere. pnpm monorepo. Drizzle ORM. Tailwind CSS. Framer Motion. Each vertical gets its own branded UI but shares authentication, event infrastructure, and a single deployment pipeline.

What I've learned:
1. Monorepos force architectural discipline — if your abstraction is wrong, you feel it immediately across 16 consumers.
2. Design tokens + shared component libraries let a solo founder maintain visual consistency across wildly different domains.
3. The hardest part isn't code — it's deciding what NOT to build next.

This isn't a demo. It's a production platform powering real operations across defense intelligence (Aegis), fleet management (Vessels), property analytics (Terra), legal matter command (PRISM Counsel), and consulting delivery (Carlota Jo).

Open to conversations with founders building multi-vertical platforms, or anyone curious about scaling a TypeScript monorepo past the "it seemed like a good idea" phase.

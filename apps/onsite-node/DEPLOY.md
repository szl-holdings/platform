# DEPLOY.md — SZL On-Site Sovereign Node: Operator Runbook

**Crusoe-style model:** move compute to the energy.  The node runs ON-SITE on
locally-generated power from otherwise-wasted energy.  Energy stays local.
Only signed results (hashes + receipts) travel home to the a11oy reservoir.

---

## What This Is (and Is Not)

**Software (built — this package):**
- `node_agent.py` — polls local energy posture, runs bounded compute workloads
  during surplus windows, signs energy receipts, posts result-hashes home.
- `node_thermal_agent.py` — exposes on-node GPU telemetry (`/gpu`, `/health`)
  as a JSON HTTP endpoint for the home app box to read over Tailscale.
- `Dockerfile` + `docker-compose.yml` — containerized deployment; arrives
  pre-wired.

**Hardware (founder/site step — NOT provided by this package):**
- A GPU-equipped server (any NVIDIA GPU that nvidia-smi can probe).
- A power source tied to a local wasted-energy source.  This is the
  site-specific capital step:
  - **Flare wellhead:** a generator/inverter on the associated gas line.
  - **Curtailed wind/solar farm:** a direct DC/AC feed from the inverter or
    grid-tie point during curtailment hours.
  - **Negative-price grid point:** a standard grid connection at a location
    where wholesale prices go negative (Germany, Texas, etc.).
- Tailscale installed on the host for secure private networking to the home
  app box (no public GPU endpoint).
- A signed CONSENT_TOKEN issued by SZL Holdings (contact ops@a-11-oy.com).

SZL provides the **software + proof layer**.  The physical tie-in to the local
energy source is a site-specific hardware and operator step.

## Hardware Requirements

| Component | Minimum | Notes |
|-----------|---------|-------|
| CPU | 2 cores | Python process only |
| RAM | 2 GB | No model serving on node by default |
| GPU | Any NVIDIA GPU | Required for MEASURED joules; SAMPLE mode works without |
| Storage | 10 GB | Container image + logs |
| Network | 1 Mbps uplink | Result-hash + receipt only (tiny payloads) |
| OS | Linux (Ubuntu 22.04 LTS recommended) | |
| Docker | 24+ | With NVIDIA Container Toolkit for GPU passthrough |
| Tailscale | Latest | For secure private networking |

**SAMPLE vs MEASURED boundary:**

| Mode | When | Joules label |
|------|------|-------------|
| SAMPLE/ESTIMATE | nvidia-smi absent or fails | Always labeled; never overclaims |
| MEASURED | nvidia-smi responds on-node | `MEASURED (on-node nvidia-smi)` |

The node runs safely in SAMPLE mode.  MEASURED mode requires the NVIDIA
Container Toolkit (`--gpus all` in compose) and a GPU physically on the host.

## Initial Setup

### 1. Install prerequisites (Ubuntu 22.04)

```bash
# Docker
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER

# NVIDIA Container Toolkit (skip if no GPU)
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor \
    -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | \
    sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
    sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
sudo apt-get update && sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker

# Tailscale
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
```

### 2. Set environment variables

```bash
# Create the .env file (NEVER commit this file)
cat > /opt/szl-node/.env <<'EOF'
HOME_URL=https://a-11-oy.com
NODE_LAT=52.5            # ← set to actual site latitude
NODE_LON=13.4            # ← set to actual site longitude
SITE_NAME=flare-well-01  # ← unique name for this node
BIND_ADDR=100.x.x.x      # ← set to Tailscale IP of this host
BIND_PORT=9101
NODE_LOOP_INTERVAL=60    # seconds between harvest cycles
MAX_JOULES_PER_WINDOW=3600
EOF
```

### 3. Set secrets (NEVER commit these)

```bash
mkdir -p /opt/szl-node/secrets
# Consent token — issued by SZL Holdings ops
echo "your-signed-consent-token-here" > /opt/szl-node/secrets/consent_token.txt
# Receipt signing key — generated by operator, registered with home mesh
openssl rand -hex 32 > /opt/szl-node/secrets/receipt_sign_key.txt
chmod 600 /opt/szl-node/secrets/*.txt
```

### 4. Build and start

```bash
cd /path/to/platform/apps/onsite-node

# Build
docker compose --env-file /opt/szl-node/.env build

# Start (with GPU passthrough)
docker compose --env-file /opt/szl-node/.env \
    -e CONSENT_TOKEN_FILE=/opt/szl-node/secrets/consent_token.txt \
    -e RECEIPT_SIGN_KEY_FILE=/opt/szl-node/secrets/receipt_sign_key.txt \
    up -d
```

## Consent and Security Model

### Consent gate

The node **never phones home without a valid `CONSENT_TOKEN`**.  This is the
operator-side gate.  The home server verifies the token's signature.
- Set `CONSENT_TOKEN` from the secret file (see Setup step 3).
- Without a valid token, the node runs locally (harvest + compute) but does not
  register or post results to the home mesh.
- Reactive/critical paths (the thermal endpoint `/gpu`, `/health`) are never
  gated — they always respond.

### Egress model

The node sends only:
1. **Result hash** (SHA-256 of the work payload) — not the payload itself.
2. **Energy receipt** (signed JSON: site, lat/lon, posture, joules_est, ts) —
   no raw inference data.

Energy never leaves the site.  Only these tiny signed packets travel home.

### Network binding

- `node_thermal_agent` binds to `BIND_ADDR` (default `0.0.0.0` for Docker
  networking; **set to your Tailscale IP in production** so only tailnet peers
  can read GPU metrics).
- Never expose port 9101 to the public internet.

## SAMPLE → MEASURED Boundary

| Condition | What happens | Label in receipts |
|-----------|-------------|-------------------|
| No GPU or nvidia-smi fails | All joule figures are estimates | `SAMPLE/ESTIMATE` |
| GPU present, nvidia-smi succeeds | Real power draw read on each cycle | `MEASURED (on-node nvidia-smi)` |

The MEASURED label is set ONLY when `nvidia-smi --query-gpu=power.draw,...`
returns a valid reading on THIS node.  The posture feeds (aWATTar, Energy-Charts,
Open-Meteo) provide a **price/surplus signal** — they tell you WHEN energy is
wasted, not HOW MANY joules your GPU is drawing.  Those are always labeled as
policy signals, not measurements.

This is honest: SZL makes no free-energy claim.  The node consumes real power;
MEASURED mode tells you how much per cycle.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|-------------|-----|
| `consent_ok: false` | CONSENT_TOKEN not set | Check secret file path in compose |
| `work_ran: false` | Posture is 'expensive' or 'normal' | Energy window not open; wait for curtailment/negative-price |
| `gpu_measured: false` | No GPU or nvidia-smi absent | Install NVIDIA Container Toolkit; check `--gpus all` |
| `/gpu` returns null metrics | nvidia-smi not found in container | Verify NVIDIA runtime: `docker run --rm --gpus all nvidia/cuda:12.0-base nvidia-smi` |
| `posted_home: false` | HOME_URL unreachable or wrong | Check HOME_URL env; verify tailnet connectivity |
| `mesh_registered: false` | Consent denied or HOME_URL unset | Check CONSENT_TOKEN and HOME_URL |

## Existing governance posture (strong)

- **Guardian gates every privileged action** — including AI-assisted actions. Pinned by tenant-isolation tests.
- **Audit log on every privileged write.** Includes the requesting principal, the action, the evidence, and the gate verdict.
- **Tier system** in Guardian — different actions require different approver tiers.
- **Rate limits** on AI-facing routes (e.g. `alloy-chat`).
- **Statement-level Postgres timeout** prevents runaway AI-generated queries from holding connections forever.
- **No new provider integrations introduced** — adapters in tree are existing, vetted, named.

## Runtime honesty (capability-aware profiles)

The brief calls out NVIDIA-style "capability-aware runtime profiles and honest fallback behavior". Today's posture:

- Provider adapters exist; runtime selection is config-driven.
- Honest fallback NOT formally surfaced to the user — when a fallback occurs (e.g. rate-limit retry to a smaller model), the user sees the result but not the route.

**Recommendation:** every AI-rendered surface should display, on hover or via a small badge: `runtime: <profile> | model: <name> | provider: <adapter>`. This is the cheapest possible move toward "explainability" and it's directly aligned with the brief's "runtime honesty" call.

## What this audit DOES NOT recommend

- Building an AI evaluation harness from scratch (out of scope; too big for one pass).
- Adding shadow/canary infra where it doesn't exist (architectural-rewrite-shaped).
- Removing or rewriting any of the existing AI route handlers (brief forbids domain rewrites).
- New model providers (brief forbids).

# SZL Holdings — Platform Overview

*For: Strategic partners, investors, and enterprise evaluators*

---

## What SZL Holdings Builds

SZL Holdings is a technology holding company that builds and operates a unified ecosystem of command-grade software platforms. Each platform addresses a specific domain where operational clarity, decision speed, and execution accountability determine outcomes: business operations, cybersecurity, real estate intelligence, maritime logistics, and premium advisory.

The defining characteristic of the SZL ecosystem is architectural unity. Every platform shares one intelligence backbone, one design system, one authentication model, and one data layer. This is not a portfolio of unrelated products — it is a compounding system.

---

## The Shared Execution Fabric: A11oy

At the center of every SZL platform is **A11oy** — the execution fabric that closes the loop from signal to confirmed action.

A11oy provides:
- **Workflow orchestration** — structured routing of operational signals to the right actor at the right time
- **Audit trail** — an immutable, attributable record of every significant decision and action
- **Human-in-the-loop gates** — required approval checkpoints for consequential operations
- **Agent coordination** — governed management of AI advisory agents across the ecosystem

When Lyte surfaces a business risk signal, A11oy routes the action. When Vessels flags a dark vessel anomaly, A11oy coordinates the response. When Aegis identifies a threat, A11oy governs the escalation path. The execution fabric is the same across every domain.

---

## The AI Intelligence Layer

Across all platforms, SZL uses a shared AI intelligence model that prioritizes:

**Explainability over opacity.** Every AI-generated recommendation includes traceable reasoning. Confidence scores, contributing signals, and evidence chains are visible — not just the conclusion.

**Advisory before autonomous.** AI agents in the SZL ecosystem analyze, synthesize, and recommend. They do not execute consequential actions without explicit human confirmation. This is an architectural commitment, enforced at the workflow level.

**Cross-domain signal correlation.** Because all platforms share an entity model and event schema, signals in one domain can inform reasoning in another. A maritime supply chain delay can surface as a commercial risk signal. A security incident affecting infrastructure can propagate to operational decision systems.

## Platform Hierarchy

### Observe · Decide · Act

**Lyte — Business Observability**
The flagship platform and operating wedge. Lyte makes every operational surface visible, contextual, and actionable through the PRISM framework (Pulse / Risk / Intelligence / Signals / Motion). Built for operations leaders, PMOs, and executive teams who need to understand organizational health in real time.

**Aegis — Unified Defense & Intelligence**
Enterprise cybersecurity and managed services command. Three unified workspaces sharing one intelligence layer: Defense (SOC operations and threat response), Command (managed services operations), and Intelligence (AI research and model governance). Built for CISOs, SOC analysts, and managed security providers.

**Terra — Real Estate Intelligence**
Property intelligence for NYC brokers, investors, and portfolio teams. Surfaces distressed properties, tracks ownership structures, and manages deal pipelines. Live data pipeline integrating multiple public data sources.

**Vessels — Maritime Intelligence**
Fleet command for maritime operators. Real-time AIS telemetry, voyage economics, route intelligence, dark vessel detection, and sanctions screening. Built for fleet executives, operations teams, and commercial directors.

### Execute

**A11oy — Execution Fabric**
The connective tissue of the ecosystem. Routes signals to action, maintains the audit trail, governs the agent network, and enforces human-in-the-loop accountability across all platforms.

### Advise

**Carlota Jo — Private Advisory**
Principal-led advisory on brand strategy, operations, and executive engagement. The advisory capability is grounded in the same observability infrastructure that underpins the platform products — intelligence-informed, not intuition-only.

## Shared Infrastructure

Every SZL platform benefits from shared investment in:

| Infrastructure | Detail |
|---------------|--------|
| Design system | `@workspace/shared-ui` — shared component library, navigation, and interaction patterns |
| Authentication | OpenID Connect (PKCE), organization-scoped RBAC |
| Database | PostgreSQL with Drizzle ORM, shared schema with domain isolation |
| API layer | Centralized Express API server for all platforms |
| Real-time | WebSocket with HMAC-signed tickets and per-channel access control |
| PDF generation | Branded document templates across all platforms |
| Email | Multi-provider delivery (Resend / SendGrid / SMTP) |
| Payments | Stripe (Checkout, Subscriptions, Invoicing) |
| Mobile | Expo / React Native for iOS and Android |
| Infrastructure | Azure Bicep IaC for enterprise deployments |

## Why This Architecture Matters

**For operators:** One place to understand operational reality across multiple domains. Shared context means signals that matter in one system surface intelligently in others.

**For enterprises:** One vendor relationship, one security posture to evaluate, one integration model. Adding a new platform vertical does not mean a new infrastructure conversation.

**For the ecosystem:** Every new platform built on this architecture compounds the value of the existing ones. The shared investment in the intelligence layer, execution fabric, and design system does not need to be made again.

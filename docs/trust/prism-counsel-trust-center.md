# Prism Counsel — Trust Center

**Version:** 1.0  
**Date:** April 2026  
**Scope:** Enterprise buyers, firm administrators, and legal operations teams

---

## Overview

Prism Counsel is a legal matter intelligence platform designed for plaintiff-side NY insurance litigation teams. It processes legal documents, attorney-client communications, medical records, and matter strategy — some of the most sensitive materials in any legal practice.

This document describes how Prism Counsel handles that data responsibly: what permissions exist, how tenant data is isolated, what AI outputs go through before they can be relied upon, how the audit trail works, and what human oversight is built into the system at the architectural level.

This is not a compliance certification document. Prism Counsel does not currently hold SOC 2, ISO 27001, or any formal third-party security certification. This document describes actual practices as they exist today.

## Permissions Model

### Role Hierarchy

Every user in Prism Counsel is assigned one or more roles. Roles determine what data can be accessed, what actions can be taken, and what AI outputs can be reviewed or approved.

| Role | Access Level | Key Capabilities |
|------|-------------|-----------------|
| `founder_admin` | Full platform | Configuration, user management, all matter data |
| `org_admin` | Organization scope | User management, org configuration, all matter data within org |
| `attorney` | Matter scope | Full read/write, export authority, approval authority |
| `paralegal` | Matter scope | Read/write on assigned matters, can submit for review; cannot approve exports |
| `operator` | Systems scope | Connector health, sync status, job queue; no matter content access |
| `analyst` | Read-only | Matter summaries and dashboards; no export |
| `client_viewer` | Limited read | Only non-privileged matter summaries; no documents |
| `external_reviewer` | Restricted | Only items explicitly shared for external review |

Role assignments are logged. A user cannot elevate their own role. Role changes require `org_admin` or `founder_admin` authority.

### Privilege State

Every document, communication, and AI-generated output in Prism Counsel carries a privilege state:

| State | Meaning | Access |
|-------|---------|--------|
| `none` | No privilege claim | Any role with matter access |
| `attorney_client` | Attorney-client privileged | `attorney`, `org_admin`, `founder_admin` only |
| `work_product` | Attorney work product | `attorney`, `org_admin`, `founder_admin` only |
| `both` | Both privileges claimed | `attorney`, `org_admin`, `founder_admin` only |

Privilege state is set at the document level (by classification or attorney assignment) and propagates to any AI output derived from that document.

**`client_viewer` and `external_reviewer` roles cannot access any privileged materials under any circumstances.** This is enforced at the retrieval level — privileged items are filtered before results are returned, regardless of UI state.

## Tenant Boundaries

Prism Counsel is a multi-tenant platform. Each law firm or legal department is an isolated tenant (identified by `orgId`).

**Isolation guarantees:**
- Every database query includes `orgId` as a required filter
- There is no cross-tenant query path in the application code
- API endpoints validate `orgId` against the authenticated user's session before executing any query
- Connector accounts (M365, etc.) are scoped to a single `orgId`
- Background jobs carry `orgId` and are processed within that scope

**What this means in practice:**
- A user at Firm A cannot access any data from Firm B, even if they know a matter ID
- A rogue query with a different `orgId` will fail authorization at the middleware level
- Multi-org users (e.g. a consultant working across two firms) must have separate accounts per org

## Review and Sign-off Expectations

Every AI output in Prism Counsel goes through a defined review workflow before it can be used in external-facing materials.

### Review States

| State | Meaning |
|-------|---------|
| `pending_review` | Generated by AI — awaiting human review |
| `reviewed` | Reviewed by a paralegal or attorney — routed to signoff |
| `approved` | Attorney-level sign-off complete — export-safe |
| `needs_revision` | Returned to author with notes |
| `archived` | Retained but excluded from active work |

### Export Safety Gate

**`exportSafe = false` by default on all AI-generated content.**

An output can only become `exportSafe = true` after:
1. The output has been reviewed (`reviewState = reviewed`)
2. An attorney (or `org_admin`/`founder_admin`) has explicitly approved it (`approvalState = approved`)

This gate is enforced at the API level. The export pipeline checks `exportSafe` on every included Proof Chain entry before generating any document. Content that has not been approved cannot be exported, regardless of UI state.

## AI Safety Notes

### Advisory-Only Output

Prism Counsel AI produces advisory outputs only. It does not:
- File documents on behalf of users
- Send communications without explicit human authorization
- Modify settlement authority or negotiation position autonomously
- Determine legal strategy without attorney review and sign-off
- Mark any AI output as legally authoritative

### Human Review is Mandatory for Legal Outputs

All Copilot reasoning outputs, document drafts, chronology sections, and demand materials require attorney review before they can be exported or sent. This is not a UI recommendation — it is enforced at the data layer through the Proof Chain review workflow.

### Source Grounding

AI outputs that make factual or analytical claims are required to include source references. Outputs with no source references receive a low confidence score and are flagged `requiresReview: true`. The system does not suppress warnings when grounding is weak — it surfaces them explicitly.

### Model Version Accountability

Every AI-generated output is tagged with:
- The model provider (openai, huggingface, azure, internal)
- The specific model version used
- The lane (embedding, reasoning, classification, etc.)
- The generation timestamp

This enables full traceability of which model version produced any given output.

## Data Handling

### What Prism Counsel Stores

| Data Category | Stored | Notes |
|--------------|--------|-------|
| Legal matter metadata | YES | Core platform data |
| Document text content | YES | After extraction — encrypted at rest |
| AI-generated outputs | YES | With proof chain anchoring |
| Attorney-client communications | YES (if synced) | Privilege-protected |
| Audit events | YES | Immutable, append-only |
| Model request logs | YES | Includes provider, model, latency, cost |
| User session tokens | YES | Short-lived, encrypted |
| M365 refresh tokens | YES | Encrypted at rest, never logged |

### What Prism Counsel Does Not Do

- Does not sell or share matter data with third parties
- Does not use matter data to train AI models
- Does not retain data after contract termination beyond the agreed retention period
- Does not access matter data for product improvement without explicit consent

### Data Retention

| Data Category | Default Retention |
|--------------|------------------|
| Matter data (active) | Retained while matter is active |
| Matter data (closed/archived) | 7 years after matter close (configurable per org) |
| Audit events | 7 years (non-configurable — legal requirement) |
| Model request logs | 90 days (configurable) |
| Document extraction outputs | Same as matter data |
| User sessions | 90 days after last activity |

## Retrieval Boundaries

Retrieval in Prism Counsel is not a single shared search index. It is a permission-aware retrieval system with the following controls:

1. **Org boundary** — All queries filter by `orgId`. No cross-org retrieval is possible.
2. **Matter access** — Users can only retrieve content from matters they have explicit access to.
3. **Role filter** — `client_viewer` and `external_reviewer` roles cannot retrieve privileged materials.
4. **Privilege filter** — `attorney_client` and `work_product` content is excluded from retrieval unless the user has an appropriate role.
5. **Export safety filter** — In export-context retrieval, only `exportSafe=true` content is returned.

ACL metadata is attached to documents at index time and re-evaluated on each sync cycle.

## Audit and Event Logging

Every significant action in Prism Counsel generates an immutable audit event.

**What is logged:**

| Category | Events |
|----------|--------|
| Model calls | Lane, provider, model version, latency, cost, status |
| AI outputs | Proof chain creation, content hash, review state changes |
| Human review | Review created, reviewed, approved, rejected — with actor ID and timestamp |
| Exports | What was exported, by whom, at what time, which proof chain entries included |
| Connector sync | Sync start, complete, fail, record counts |
| User access | Login, logout, role-elevated action |
| Approval workflow | Request created, resolved, escalated |
| Data changes | Matter created/updated, deadline added, party added |

**Audit event properties:**
- `orgId` — Tenant scoping
- `actorId` — Who performed the action
- `actorType` — user / system / service
- `action` — What happened
- `entityType` / `entityId` — What was affected
- `details` — Structured context (JSON)
- `createdAt` — Immutable timestamp

Audit events are append-only. No delete operation exists on `pc_audit_events`. No user, including `founder_admin`, can delete audit events.

## Proof Chain and Source Trace

Every AI output is anchored to a Proof Chain entry that includes:
- SHA-256 hash of the output content (integrity verification)
- Source references (what documents/signals informed the output)
- Model version that produced it
- Confidence score
- Review and approval state
- Export safety flag

This enables:
- Verifying that an output has not been modified since generation
- Tracing any factual claim back to its source document
- Demonstrating that an approved output went through the required review workflow
- Identifying which model version was responsible for any given analysis

See full specification: [Proof Chain Specification](../architecture/prism-counsel-proof-chain-spec.md)

## M365 Deployment Considerations

When Prism Counsel is connected to a Microsoft 365 tenant:

- App-only permissions are requested at the minimum necessary scope
- No write permissions to M365 are requested or used
- Refresh tokens are stored encrypted and never logged
- Graph subscription notifications are validated using `clientState` secrets
- All sync operations are logged as audit events
- Synced content is subject to the same permission model as manually uploaded content — privilege state is preserved from SharePoint sensitivity labels where available

See: [M365 Integration Strategy](../architecture/prism-counsel-m365-integration.md)

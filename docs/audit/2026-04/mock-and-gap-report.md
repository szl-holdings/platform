**Audit date:** April 18, 2026  
**Priority key:** P0 = blocks trust / production safety | P1 = blocks sales / demo | P2 = degrades credibility | P3 = cleanup / polish

## P0 — Safety / Trust Blockers

### P0-001: Admin seed endpoint has no confirmed production guard
**Artifact:** `api-server` — `src/routes/admin/seed.ts`  
**Issue:** The `/api/admin/seed` endpoint seeds destructive demo data. `RUNTIME_MODE` and `DEMO_MODE` checks exist in startup validation, but the seed endpoint's own guard against `NODE_ENV=production` or `RUNTIME_MODE=production` has not been verified in code. In a misconfigured deployment this could corrupt live data.  
**Evidence:** `ENABLE_DEMO_SEED` env var controls auto-seed at startup; route-level guard for the manual POST endpoint is unconfirmed.  
**Remediation:** Add explicit `if (process.env.NODE_ENV === 'production' || process.env.RUNTIME_MODE === 'production') return 403` guard at route entry.

### P0-002: Input validation covers only 12% of API routes
**Artifact:** `api-server`  
**Issue:** 21 of 170 top-level route files use Zod validation helpers. The remaining 149 routes accept untrusted input without schema enforcement, creating injection and malformed-data risk.  
**Evidence:** `docs/known-gaps.md` — explicitly documented.  
**Remediation:** Apply Zod validation to all routes that accept a body or query params. Existing `validateBody`/`validateQuery` helpers are in place.

## P1 — Sales / Demo Blockers

### P1-001: Maps are blank in Terra (Mapbox token missing)
**Artifact:** `terra`  
**Issue:** No `MAPBOX_TOKEN` configured. All map-based views (spatial walkthrough, neighborhood momentum, climate risk) render blank.  
**Impact:** Demos of Terra's spatial intelligence are not presentable.  
**Remediation:** Set `MAPBOX_TOKEN` in environment secrets. (Free tier sufficient for demos.)

### P1-002: AIS telemetry is fully simulated — "live fleet" claim is false
**Artifact:** `vessels`, `szl-holdings`  
**Issue:** Vessel positions are generated by `pubsub-bridge.js`, not a real AIS feed. The UI shows a `DemoModeBanner` in Vessels ("Live AIS feed not connected — showing cached vessel positions · data may be up to 60 min old"), but the `szl-holdings` dashboard claims "52,000+ vessels monitored" with no demo qualifier.  
**Impact:** Investor or prospect confusion about live maritime capability.  
**Remediation:** Add demo qualifier to all "vessels monitored" claims on `szl-holdings`. Remove or badge any UI showing AIS data as live. AIS subscription ($15–40K/yr) tracked as a revenue-phase decision.

### P1-003: Hardcoded operational claims on szl-holdings dashboard are unverifiable
**Artifact:** `szl-holdings`  
**Issue:** Dashboard and marketing copy contain: "52,000+ vessels monitored," "2.4M+ signals processed per day," "< 4 min average signal detection time," "31,200+ simulations executed," "34 days before formal designation" (dark vessel lead time). None of these are derived from live instrumentation.  
**Impact:** Material misrepresentation risk in investor or enterprise presentations.  
**Remediation:** Replace hardcoded numbers with either (a) registry-sourced values tagged `[demo]`, or (b) remove until live instrumentation confirms them.

### P1-004: Pulse briefing falls back silently to synthetic drift data
**Artifact:** `pulse`, `api-server/src/routes/pulse.ts`  
**Issue:** When no AI provider key is available, the system generates a briefing by drifting prior scores — this is functionally indistinguishable from a real AI briefing in the UI. No visible fallback label is shown.  
**Remediation:** Add a "Synthesized (no AI provider)" badge when the fallback path is taken. Ensure API keys are set for demo environments.

### P1-005: 8 new Aegis security modules not wired to live API
**Artifact:** `aegis`  
**Issue:** APP_STATUS.md confirms "8 new security modules not wired to live API/case management." Buttons exist in the UI that trigger dead or stub endpoints.  
**Remediation:** Either wire to api-server stub responses with clear demo labels, or hide behind a feature flag until real wiring is complete.

### P1-006: Three Vessels commercial modules not connected to DB
**Artifact:** `vessels`  
**Issue:** Insurance, trading, and platform modules exist in the route tree but have no DB or API backing.  
**Remediation:** Wire to seed data with demo badge, or feature-flag to hide.

### P1-007: Command dashboard badge counts not wired to live API
**Artifact:** `command`  
**Issue:** CORTEX cross-domain badge counts (alerts, approvals, exceptions) are demo-fixture values, not derived from live api-server state.  
**Remediation:** Wire `GET /api/core/metrics` or equivalent to populate badge counts dynamically.

## P2 — Credibility Degraders

### P2-001: "98% client retention" claim in Carlota Jo is hardcoded
**Artifact:** `carlota-jo/src/pages/PremiumHome.tsx`, `AdvisoryIntel.tsx`, `pulse.tsx`  
**Issue:** The 98% figure appears in three places as a hardcoded string. There is no CRM or cohort data backing it.  
**Remediation:** Either remove or source from a real client retention calculation, or explicitly label as "historical target."

### P2-002: "18 years of private advisory experience" claim is hardcoded
**Artifact:** `carlota-jo/src/pages/PremiumHome.tsx`  
**Issue:** Rosa Carlota Jo's experience claim ("18 years") is a static string. If the site persists into 2027 without an update, it will be wrong.  
**Remediation:** Derive from a `founderStartYear` registry value so it increments automatically, or acknowledge as a one-time claim to be periodically reviewed.

### P2-003: "99.98% uptime" claim on Command marketing/status page is fabricated
**Artifact:** `command/src/pages/marketing/status.tsx`  
**Issue:** The status page shows 99.98% uptime and 71ms response time for "Aegis — Defense Intelligence." These figures come from a hardcoded data file, not a real uptime monitor.  
**Remediation:** Either connect to a real uptime monitor (UptimeRobot, Betterstack, etc.) or remove the status page from public-facing paths.

### P2-004: "$4.2B+ assets under analysis" (Terra/szl-demo-video) is seed data
**Artifact:** `szl-demo-video`, `aegis/src/pages/slides/S11Market.tsx`  
**Issue:** $4.2B appears as "AUM" in the demo video and as market sizing in the pitch deck. In the demo video it represents seed portfolio data, not real AUM.  
**Remediation:** Label as demo in video. Pitch deck usage (market sizing, not AUM) should be clearly scoped in slide context.

### P2-005: Analytics events are not confirmed to be flowing
**Artifact:** All web artifacts  
**Issue:** PostHog SDK is referenced in `lib/analytics` and `sentinel-analytics`, but the task queue has a confirmed gap: "Connect the analytics events to a real analytics provider so conversion data is actually captured."  
**Remediation:** Existing open task; confirm PostHog API key and verify events with live dashboard.

### P2-006: Demo reset requires terminal access — no in-app trigger
**Artifact:** `api-server` / `scripts/demo-reset/`  
**Issue:** Resetting demo state requires SSH/CLI. Presenters in live demos cannot recover if data drifts.  
**Remediation:** Existing open task ("Add a one-click demo reset button inside the platform").

### P2-007: Carlota Jo Consulting OS data is entirely hardcoded
**Artifact:** `carlota-jo/src/data/operationalData.ts`  
**Issue:** Engagement P&Ls, team rates, client health scores, and capacity alerts are all static fixture data. The Consulting OS is presented as an operational tool.  
**Remediation:** Label as "Demo data" within the Consulting OS views, or source from real time-tracking/CRM data.

### P2-008: PDF export in Pulse is not implemented
**Artifact:** `pulse`  
**Issue:** The "Export PDF" button exists in briefing reader but has no implementation.  
**Remediation:** Existing open task ("Add working PDF export to the Pulse briefing reader").

### P2-009: Generic "Simulated" / "Demo" badges inconsistently applied
**Artifact:** All artifacts  
**Issue:** Terra shows a `DataProvenance` component with live/demo status. Vessels shows a `DemoModeBanner` for AIS. Command and szl-holdings have no consistent demo-mode labeling on seeded dashboard KPIs.

### P2-010: Firestorm seed endpoint path is public in codebase docs

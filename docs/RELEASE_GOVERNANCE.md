# SZL Holdings — Release Governance

## Release Pipeline

Every release follows a governed pipeline with evidence collection at each stage.

### Pipeline Stages

| Stage | Gate | Evidence |
|-------|------|----------|
| Install | Dependency resolution succeeds | `pnpm install` exit code |
| Typecheck | Zero TypeScript errors | `tsc --noEmit` output |
| Lint | Zero critical lint violations | ESLint report |
| Build | All artifacts compile | Build log per artifact |
| Unit Tests | All tests pass | Test runner output |
| Integration Tests | API contracts verified | Smoke test results |
| E2E Tests | Critical user paths verified | Playwright reports |
| Security Scan | No critical vulnerabilities | Dependency audit + SAST output |
| Metrics Generation | Platform metrics computed | `generated/platform-metrics.json` |
| Health Check | All services respond 200 | Health endpoint responses |

### Release Types

| Type | Approval Required | Scope |
|------|------------------|-------|
| Patch | Engineering lead | Bug fixes, dependency updates |
| Minor | Engineering lead + Product | New features, UI changes |
| Major | Engineering lead + Product + Executive | Breaking changes, architecture shifts |
| Security | Engineering lead + Security lead | Vulnerability remediation |

### Provenance

Each release includes:
- Git commit SHA and branch
- Build timestamp
- CI pipeline run ID
- Test evidence snapshot
- Platform metrics at time of release
- Known risks documented in release notes

### Release Artifacts

Generated by `scripts/audit/generate-platform-metrics.ts`:
- `generated/platform-metrics.json` — machine-readable metrics
- `generated/platform-metrics.md` — human-readable report

Generated by `scripts/evals/run-arena.ts`:
- `generated/arena-results/` — evaluation results per run

### Rollback Policy

- All deployments support instant rollback via Replit deployment system
- Database migrations are forward-only; destructive changes require explicit approval
- Feature flags enable gradual rollout with kill switch capability

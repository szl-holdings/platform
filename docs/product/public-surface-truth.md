# Public Surface Truth

The public-surface registry separates three facts that older product inventories mixed together:

1. a source tree or product concept exists;
2. a public URL is currently routed; and
3. the content behind that URL is live, modeled, documented, or unavailable.

The reviewed source is [`config/public-surfaces.json`](../../config/public-surfaces.json). The
deterministic output is
[`artifacts/PUBLIC_SURFACES.json`](../../artifacts/PUBLIC_SURFACES.json). Its overlapping measured
product value also feeds the internal claims-drift artifact; this page intentionally publishes no
canonical quantitative claim. Public platform counts remain governed by the metrics registry and
generated [`docs/platform-facts.md`](../platform-facts.md).

## Vocabulary

`availability` describes only the measured HTTP route:

- `REACHABLE` — the canonical URL returned the recorded successful status without redirecting;
- `REDIRECTED` — the canonical URL returned a successful final response at the recorded target;
- `UNAVAILABLE` — the route returned the recorded HTTP failure and is not counted as routed.

`mode` describes the evidence boundary of the surface:

- `LIVE` — the surface performs a runtime verification or exposes runtime state;
- `MIXED` — the surface contains more than one evidence state, such as live, modeled, snapshot,
  sample, cached, or unavailable;
- `DOCUMENTATION` — the surface is explanatory material, not runtime proof;
- `UNAVAILABLE` — the route is not available.

Route reachability is not uptime, customer adoption, feature completeness, or correctness proof.
Item-level receipts and evidence labels remain authoritative.

The generated summary keeps product and route granularity separate:

- `customer_facing_products` counts distinct qualifying non-documentation
  `source_owner.repository` values;
- `customer_facing_routes` counts every qualifying routed web page, including documentation-only
  owners that do not increase the product count.

Only the distinct-owner value feeds the internal `surfaces_customer_facing` drift signal, so a new
documentation page or route cannot be misreported as a new product. It is not a public platform
statistic until it is incorporated into the governed metrics registry and generated platform facts.

## Developer workflow

```bash
# Regenerate the deterministic artifact after an evidence refresh.
pnpm surfaces:generate

# Verify schema, generated bytes, and every recorded live HTTP result.
pnpm surfaces:check

# The daily/manual lifecycle gate adds the seven-day observation-age audit.
pnpm surfaces:freshness

# Run the focused fail-closed tests.
pnpm exec tsx --test tools/truth/public-surfaces.test.ts
```

Any changed route, redirect, status, source owner, or evidence mode requires a new observed
timestamp and a reviewed registry update. The existing `truth-drift` workflow runs
`surfaces:check`; snapshot age alone does not expire unrelated CI. No separate or weaker protected
status context is introduced.

The same workflow runs `surfaces:freshness` daily at `06:17 UTC` and when a manual run explicitly
sets `require_surface_freshness`. If that lifecycle gate fails, re-observe every approved target,
update `observed_at` and any changed observation fields in `config/public-surfaces.json`, run
`pnpm surfaces:generate`, inspect both deterministic artifacts, and rerun
`pnpm surfaces:freshness` before presenting the snapshot as current.

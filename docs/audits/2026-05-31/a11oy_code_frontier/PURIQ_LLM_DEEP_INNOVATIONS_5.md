## D1. 13-Axis Yuyay LLM Distillation

**Concept.** Fine-tune a small open base (Llama 3.3 8B AMBER, or **Qwen3-8B / OLMo 3 7B GREEN — preferred for license**) to *natively emit the 13 `yuyay_v3` axis scores as structured logits*, so the gate is computed *by the model* rather than by a separate classifier. We own this model class: "the Yuyay model."

**Why it matters.** Today the 13-axis gate is an external evaluation step. A model that natively predicts the 2 sacred (≥0.95), 7 structural (≥0.90), and 4 introspection axes makes gating a single forward pass — faster, cheaper, and *ours*. It is the first model in the world whose output head *is* a governance gate.

**Technical design.**
- Base: **OLMo 3 7B** (Apache-2.0, fully-open data/recipe — strongest Khipu provenance fit, `MISSING_LLMS_2026.md` §7.1) or Qwen3-8B (Apache-2.0).
- Add a 13-dim regression/classification head emitting `yuyay_v3` axis scores; the conjunctive-AND gate (0 unless all 13 clear floors) is computed from the head.
- Training data: pairs `(proposal, 13 axis scores)` from the existing gate's evaluation logs (the gate is the teacher → cheap distillation). Use **Tülu 3 RLVR recipe** (AllenAI, open) for the post-training; reward = agreement with the locked gate.
- License gate: teacher must allow training-on-outputs — use the existing *our-own-gate* labels (no third-party model-output restriction); if augmenting with synthetic data, use **NVIDIA Nemotron-4-340B** (license explicitly permits training on outputs — `MISSING_LLMS_2026.md` §4.1), **never Grok 2** (no-train clause).
- Replay-hash `bacf5443…631fc5` is preserved: the distilled model's gate output must *match the canonical gate* on the replay set (this is the acceptance test — INV below).

**Cost:** XL (model training + eval harness).

**Competitive landscape.** *Closest commercial:* OpenAI/Anthropic safety classifiers (separate moderation models, not a governance head on the reasoning model); constitutional-AI critique models ([Bai et al., "Constitutional AI," 2022, arXiv 2212.08073](https://arxiv.org/abs/2212.08073)). *Academic precedent:* reward-model distillation ([Lee et al., "RLAIF," 2023, arXiv 2309.00267](https://arxiv.org/abs/2309.00267)); Tülu 3 RLVR ([Lambert et al., "Tülu 3," 2024, arXiv 2411.15124](https://arxiv.org/abs/2411.15124)). *Structural difference:* the governance gate is a *native output head trained to match a locked, hash-anchored reference gate*, not an external moderator.

**Khipu/PURIQ tie-in.** The model *is* `Yuyay₁₃(a)` in the master formula `P(x,t)`.

## D2. Khipu-Aware Fine-Tuning

**Concept.** Fine-tune a base model to *embed Khipu receipt anchors directly in its token stream* — special tokens that mark "this span is a receiptable claim" with an inline `content_hash` placeholder the runtime fills. The model learns *where* receipts belong.

**Why it matters.** Innovation #1 (Khipu-signed reasoning) bolts receipts on *after* generation. A Khipu-aware model emits the receipt boundaries *natively*, so the receipt DAG is a first-class part of generation, not post-hoc parsing. The model learns the discipline of "every claim is receiptable."

**Technical design.**
- Add special tokens `<khipu_open id=...>` … `<khipu_close hash=...>` to the tokenizer.
- Fine-tune on data where claims are wrapped in these tokens (generated by running the existing receipt plumbing over a corpus → self-supervised labels).
- At inference, the runtime computes the hash for each closed span and links it into the DAG (the model emits the *structure*; the runtime emits the *cryptography*).
- Compatible with any GREEN base (Qwen3, OLMo 3, DeepSeek distill). Reuses in-toto serialization (Killinchu path).

**Cost:** L–XL (tokenizer surgery + fine-tune + runtime linkage).

**Competitive landscape.** *Closest commercial:* function-calling / tool-token training (OpenAI, Hermes 4 structured output — `OPEN_LLM_LANDSCAPE` §2.12); citation-token training (Cohere Command grounded generation). **None trains a model to emit cryptographic-receipt boundaries.** *Academic precedent:* special-token tool training ([Schick et al., "Toolformer," 2023, arXiv 2302.04761](https://arxiv.org/abs/2302.04761)); citation/attribution training ([Gao et al., "RARR," 2022; Menick et al., "GopherCite," 2022, arXiv 2203.11147](https://arxiv.org/abs/2203.11147)). *Structural difference:* receipt boundaries are *native generated structure*, hash-linked at runtime.

**Khipu/PURIQ tie-in.** Native generation of the `∏Khipu_i(a)` boundaries.

## D3. PURIQ-Formula-as-Tool

**Concept.** Expose the **23 PURIQ formulas** — especially the **13 PROVED Lean theorems** (F1-half, F3, F9, F10a, F11, sieve, Bézout, F15, F19a, F20, F21, F23 — per Formula-Mining PONDER 03:30) — as *callable tools* the LLM invokes mid-reasoning, in the Tool-Integrated-Reasoning (TIR) style that Qwen2.5-Math uses (`MISSING_LLMS_2026.md` §5.2).

**Why it matters.** Instead of the model *approximating* `P(x,t)`, `Λ`, or a Bekenstein bound in natural language, it *calls the proved theorem* and gets the certified result. The brain's arithmetic becomes mechanically correct — the Lake-verification idea (#10) applied to our *own* formula corpus.

**Technical design.**
- Wrap each of the 13 PROVED theorems + 10 numeric harnesses (all 50/50 PASS per `harness_selfcheck.py`) as JSON-schema tools: `lambda_aggregate(x, w)`, `bekenstein_bound(budget)`, `puriq_utility(lambda, yuyay, hukla, khipu, beta)`, `noether_charge(receipt)`, etc.
- The model (Qwen2.5-Math-style TIR or any tool-calling GREEN model) calls them; results are *certified by the Lean corpus* and receipted.
- Bounded calls (fuel-limited, Turing-honest F19); each call is a Khipu step (ties to #1).
- The 3 conjecture-axioms (Gauss-Bonnet F13, Hardy-Ramanujan F14, Feynman fiber-collapse F22) are exposed but *labeled conjecture* — honesty preserved (HR-4): a tool result derived from a conjecture is tagged.

**Cost:** M (tool-wrapping the existing Lean/harness corpus; TIR plumbing exists in the math models).

**Competitive landscape.** *Closest commercial:* Wolfram plugin, code-interpreter (general computation, not a *proved-theorem* corpus); OpenAI function calling. **No product exposes its own formally-verified theorem corpus as callable tools.** *Academic precedent:* Tool-Integrated-Reasoning ([Qwen2.5-Math, arXiv 2409.12122](https://arxiv.org/html/2409.12122v1)); PAL ([Gao et al., ICML 2023, arXiv 2211.10435](https://arxiv.org/abs/2211.10435)); LeanDojo ([Yang et al., NeurIPS 2023, arXiv 2306.15626](https://arxiv.org/abs/2306.15626)). *Structural difference:* the tool corpus is *our own 13 PROVED theorems*, conjectures honestly labeled.

**Khipu/PURIQ tie-in.** The model computes `P(x,t)` by *calling* its certified components; each call receipted.

## D5. Anatomy MoE — Organ-as-Expert

**Concept.** A genuine **Mixture-of-Experts architecture where each expert *is* an organ**: an Amaru-expert (governance/provenance), a Yuyay-expert (cognition), a Killinchu-expert (maritime), a Sentra-expert (security), etc. Routing is done by the **Λ-spine** (the existing aggregator), not a learned softmax gate. Train via instruction tuning per organ; route via the Λ-spine. Genuine architectural novelty — the anatomy *is* the model.

**Why it matters.** Today the organs are *prompting/routing roles* over shared models (Innovation #6). D5 makes the anatomy *intrinsic to the weights*: the model has an organ for each governance function, and the Λ-spine — a *principled, bounded, monotone aggregator* (Doctrine v11 §12 D2, not a black-box gate) — decides which organ handles which token. This is the deepest possible expression of "bake every organ into the brain."

**Technical design.**
- Start from an open MoE base — **OLMoE-1B-7B** (Apache-2.0, *fully open* MoE: data+code+logs — the only fully-reproducible MoE, `MISSING_LLMS_2026.md` §7.1) or Qwen3-MoE / Jamba (hybrid SSM-MoE).
- Re-purpose / re-train experts so each maps to an organ: continued instruction-tuning per organ on organ-specific data (amaru on provenance/receipt tasks, sentra on security triage, killinchu on maritime/legal, etc.).
- **Replace the learned router with the Λ-spine**: the gating decision is `Λ(x) = ∏ xᵢ^{wᵢ}` (positive-homogeneous, bounded, monotone — the proved D2 aggregator) over the context's axis vector, producing organ weights. This is the novel part: a MoE whose router is a *proved, interpretable aggregator*, not an opaque linear layer.
- Each expert's output carries its organ's Khipu receipt; the combined output's provenance is the weighted set of organ receipts.
- Honesty: Λ-uniqueness is **Conjecture 1, NOT a theorem** (Doctrine v12 §2 honest label) — the router uses Λ as the *canonical D2 aggregator*, not as the unique one. The architecture does not assume uniqueness.

**Cost:** XL (MoE re-training + custom routing layer + per-organ data).

**Competitive landscape.** *Closest commercial:* Mixtral/DBRX/Llama 4 MoE (learned routers, opaque experts); Snowflake Arctic dense-MoE. **No production model routes a MoE by a formally-specified, monotone, interpretable aggregator, nor binds experts to named governance roles.** *Academic precedent:* sparse MoE ([Shazeer et al., "Outrageously Large Neural Networks," ICLR 2017, arXiv 1701.06538](https://arxiv.org/abs/1701.06538)); Switch Transformer ([Fedus et al., JMLR 2022, arXiv 2101.03961](https://arxiv.org/abs/2101.03961)); OLMoE ([Muennighoff et al., 2024, arXiv 2409.02060](https://arxiv.org/abs/2409.02060)); modular/expert-specialization ([Gururangan et al., "DEMix," 2021, arXiv 2108.05036](https://arxiv.org/abs/2108.05036)). *Structural difference:* experts are *governance organs*, the router is the *proved Λ-spine*, every expert output is receipted.

**Khipu/PURIQ tie-in.** The architecture literally instantiates the anatomy; the Λ-spine routing is the `Λ(x)` factor of `P(x,t)`; each expert output is a `Khipu_i`.

# Request Triage Playbook

## Step 1: Receive
- Log in feedback system (once DB-backed)
- Auto-acknowledge to submitter
- Tag with product, type, source

## Step 2: Classify
- Bug → Check severity, check duplicates, assign to engineering
- Feature Request → Assess impact, check duplicates, add to backlog
- General Feedback → Tag theme, add to weekly review

## Step 3: Prioritize

### Bug Triage
| Severity | Response | Fix Timeline |
|----------|----------|-------------|
| Critical | Immediate | Same day |
| High | Within 4 hours | Within 1 week |
| Medium | Within 24 hours | Next sprint |
| Low | Within 1 week | Backlog |

### Feature Request Triage
| Impact | Demand | Decision |
|--------|--------|----------|
| High | Multiple requests | Plan immediately |
| High | Single request | Evaluate feasibility |
| Medium | Multiple requests | Add to backlog |
| Medium | Single request | Note and monitor |
| Low | Any | Defer or decline |

## Step 4: Communicate
- Acknowledge receipt
- Share status when triaged
- Update when planned or in-progress
- Notify when released
- Explain when declined

## Step 5: Close Loop
- Verify fix (for bugs)
- Confirm satisfaction (for features)
- Note in release notes (if significant)
- Update FAQ (if recurring theme)

# Feedback Operating Model

## Purpose
Capture, categorize, and act on feedback from users, buyers, and stakeholders.

## Intake Channels
1. Bug reports (/help/report-a-bug + support@szlholdings.com)
2. Feature requests (/help/request-a-feature + feedback@szlholdings.com)
3. General feedback (/help/feedback + feedback@szlholdings.com)
4. Post-demo feedback (demo follow-up)
5. In-product feedback (planned)

## Status Model
new → triaged → planned → in-progress → released / declined

## Processing Rules
- Bug reports triaged within 24 hours
- Feature requests triaged within 1 week
- General feedback reviewed in weekly product review
- All feedback logged and tagged by product area
- Patterns inform roadmap priorities
- Significant feedback acknowledged directly

## Connections
- Feedback → Release notes (shipped features reference feedback)
- Feedback → Product analytics (measure impact of changes)
- Feedback → Support center (FAQ generated from common feedback)
- Feedback → Roadmap (feature requests inform priorities)

- Intake paths documented

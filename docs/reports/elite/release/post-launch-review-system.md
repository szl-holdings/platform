# Post-Launch Review System

## Purpose
Every release gets a post-launch review to learn from what went well and what could improve.

## Timing
- **Patch**: Optional review (only if issues encountered)
- **Minor**: Review within 72 hours
- **Major**: Review within 72 hours, mandatory

## Template
See elite-layer/release-governance/post-release-review.md

## Review Metrics
1. Error rate before/after
2. Response time before/after
3. User impact (tickets, feedback)
4. Feature adoption (if new feature)
5. Time from merge to full deployment

## Review Outputs
- What went well (keep doing)
- What could improve (action items)
- Issues encountered (with resolution)
- Release score (1-5 across 4 criteria)

## Action Items
- All action items are tracked
- Owner and deadline assigned
- Reviewed in next release planning
- Systemic improvements noted for process updates

## Cadence
- Individual release reviews: Per release schedule
- Monthly rollup: Summary of all releases that month
- Quarterly retrospective: Themes, process improvements

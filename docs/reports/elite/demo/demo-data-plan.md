# Demo Data Plan

## Principles
- Demo data must look intentional and premium
- No lorem ipsum or obviously fake names
- Data should tell a coherent story per product
- Every demo scenario should have a clear narrative
- Demo data is clearly labeled as illustrative

## Per-Product Demo Data Sets

### Lyte
- 10 signals (mix of priorities: 2 critical, 3 high, 3 medium, 2 low)
- 5 pending approvals
- 3 completed workflows
- Executive summary with realistic metrics

### Terra
- 20 properties across 3 markets
- 3 distress alerts with context
- 5 active deals at different pipeline stages
- Market comparables for each area

### Vessels
- 15 vessels with different statuses
- 5 active voyages with economics
- 3 exceptions (maintenance, compliance, route)
- Fleet map with geographic spread

### Aegis
- 8 incidents (2 active, 3 investigating, 3 resolved)
- 5 threat intel items
- MITRE ATT&CK mapping examples
- Governance dashboard metrics

### Carlota Jo
- 3 sample services with descriptions
- 2 available time slots for booking demo
- Sample client portal with 2 documents

## Data Refresh
- Demo data should be refreshed monthly
- No stale dates (auto-update relative dates if possible)
- Clean up any data drift from testing

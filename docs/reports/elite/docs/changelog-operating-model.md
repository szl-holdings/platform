# Changelog Operating Model

## Process
1. Every significant change is documented in content/changelog/index.md
2. Major releases get full release notes in content/changelog/releases.md
3. Breaking changes are tracked separately in content/changelog/breaking-changes.md

## Categories
- Added — New features
- Changed — Modifications
- Fixed — Bug fixes
- Security — Security improvements
- Deprecated — Planned removals
- Removed — Features removed

## Cadence
- Changelog: Updated with every release
- Release notes: Published for major and minor versions
- Monthly release recap: Published using template

## Ownership
- Engineering team writes technical changelog
- Product team writes user-facing release notes
- Owner reviews and publishes

## Distribution
- Published on /changelog page
- Major releases announced in newsletter
- Security changes noted in trust updates

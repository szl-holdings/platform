==================================================

ROLES
- public
- authenticated
- member
- client
- editor
- admin
- super_admin

ROLE INTENT
public:
- can view public pages

authenticated:
- signed-in baseline user

member:
- org member for product dashboards

client:
- client portal access for Carlota Jo

editor:
- content editing in allowed scopes

admin:
- admin controls for site/org

super_admin:
- full ecosystem control

PERMISSION GUIDELINES
public:
- read published public content only

authenticated:
- read own profile
- update own profile

member:
- read org-authorized product data
- create/update limited product actions depending on product

client:
- access only own client account documents/updates/messages

editor:
- manage content records in assigned sites
- publish content if granted

admin:
- manage site settings
- manage content
- manage org members where appropriate
- view analytics
- manage forms and leads

super_admin:
- manage all sites
- manage all orgs
- full admin and audit visibility

==================================================
SECTION 15: RLS / SECURITY IMPLEMENTATION RULES
==================================================

NON-NEGOTIABLES
- enable RLS on all protected tables
- default deny
- create explicit read/write policies
- public content must be separated from protected data
- organization_id must exist on org-scoped data
- use auth.uid() for profile and membership checks
- index policy-critical foreign keys
- keep admin write paths server-side where possible
- do not leak secrets in client bundles

PUBLIC CONTENT POLICY PATTERN
Allow public read only where:
- status = published
and
- site/page/record is public

ORG DATA POLICY PATTERN
Allow read/write only where:
- auth user belongs to organization via organization_memberships
and
- role is sufficient for action

CLIENT DATA POLICY PATTERN
Allow access only where:
- authenticated user maps to client account membership or ownership
- record belongs to that client account / organization

ADMIN POLICY PATTERN
Admin actions should require:
- editor/admin/super_admin membership checks
- ideally via secured server actions or API routes

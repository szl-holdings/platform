2. PLATFORM RULES
==================================================

Build one shared platform, not seven disconnected apps.

Every app must use these shared services:
- /packages/auth for session and RBAC
- /packages/db for schema and database access
- /packages/integrations for third-party connectors
- /packages/observability for logs, health, metrics, audit trail
- /packages/notifications for email, SMS, Slack alerts
- /packages/billing for usage plans and Stripe readiness
- /packages/ui for shared premium components and design tokens

Create a universal connector framework:
Each external integration must be represented by:
- connector definition
- auth config
- health check
- sync method
- webhook handler
- status record
- last sync timestamp
- failure state
- retry logic

Do not hardcode fake live calls that break when secrets are missing.
If credentials are absent:
- show connector as "Not Connected"
- render a polished setup screen
- keep the app functional in demo mode
- seed demo records so every workflow is visible

11. REPLIT-SPECIFIC EXECUTION RULES
==================================================

This project is being built for Replit.

Requirements:
- ensure the server listens on 0.0.0.0
- use Replit SQL Database for relational persistence
- use Replit storage for files/assets
- use Replit Secrets / deployment secrets for all credentials
- never commit secrets
- do not rely on local filesystem persistence for live deployments
- keep build and run commands explicit and working
- include .env.example with all required variables documented
- include seed scripts for demo mode
- make the app publishable from Replit without manual code surgery

If an app is public-facing, make it deployment-ready.
If an app is internal-facing, prepare it for private deployment and RBAC.

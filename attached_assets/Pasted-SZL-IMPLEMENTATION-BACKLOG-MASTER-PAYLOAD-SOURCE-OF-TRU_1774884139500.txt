6. RLS / AUTHORIZATION PLAN
==================================================

Implement auth + authorization at the database layer.

RLS POLICY MODEL
- users can only see organization data they belong to
- pilot_customer_user sees only scoped organization rows
- executive_viewer gets read-only access to approved/visible records in org scope
- platform_admin and founder_admin have elevated internal access
- service_coordinator only sees Carlota/internal workflow data in allowed scope
- artifact access is restricted by org + role + approval state where needed

REQUIRED AUTH BEHAVIOR
- public routes do not require auth
- private routes require login
- DB access must be scoped by org membership and role
- object fetch by id must still pass authorization
- never trust client-side filtering as access control

AUTH FLOW
- email/password or magic link for internal/pilot access
- optional future SSO for enterprise pilots
- include invitation flow later if needed, but not phase-one critical

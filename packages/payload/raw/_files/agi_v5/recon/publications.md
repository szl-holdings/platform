## 1. Executive Summary (≤200 words)

**Top 3 leaders by area:**

1. **AGI Capability Forecasting — METR (leaders).** [METR's March 2025 paper](https://metr.org/blog/2025-03-19-measuring-ai-ability-to-complete-long-tasks/) established the 50%-task-completion time horizon metric with a measured doubling time of ~7 months since 2019. As of May 2026, Claude Khipu Preview exceeded METR's 16-hour measurement ceiling. [Epoch AI's Trends dashboard](https://epoch.ai/trends) quantifies training compute growing at 5×/year since 2020 and AI chip stock doubling every 7 months. These orgs own the quantitative forecasting discourse.

2. **Formal Verification of LLM Systems — DeepMind AlphaProof (leaders).** [AlphaProof (Nature, Nov 2025)](https://www.nature.com/articles/s41586-025-09833-y) reached silver-medal IMO performance using RL over Lean proofs. [Lean Copilot (arXiv 2404.12534)](https://arxiv.org/abs/2404.12534) automates 74.2% of Lean proof steps.

3. **Multi-Agent Governance — IETF SCITT + Google A2A (leaders).** [IETF SCITT architecture](https://datatracker.ietf.org/wg/scitt/) is in RFC Ed Queue; [Google A2A protocol](https://developers.googleblog.com/en/a2a-a-new-era-of-agent-interoperability/) (April 2025, now Linux Foundation) has 50+ enterprise partners.

**Where we are genuinely ahead:** No published system combines cryptographic receipt chains, Lean-formal Λ-gate calculus, and 9-axis conjunctive moral grounding in one runtime. Our Curry-Howard-for-agents approach (TH7 in Math Pod V3) has no direct peer in any 2024–2026 publication found.

**Where we are genuinely behind:** METR/Epoch quantitative AGI dashboards, AlphaProof's RL-over-formal-proof engine, and the A2A interoperability ecosystem all outpace our current published work.

## 4. Originality Gap — 5 Concrete Overlaps with Our Claims

### Gap 1: Runtime Orchestration with State Tracking

**They did:** [Magentic-One (Microsoft, arXiv 2411.04468)](https://arxiv.org/abs/2411.04468) built a generalist multi-agent orchestrator with a dual-ledger system (Task Ledger + Progress Ledger) achieving 38% on GAIA, 32.8% on WebArena. AutoGen 0.4 provides the underlying framework.

**We did:** ouroboros runtime v6.3.0 — receipt-stamped execution with p50 11.5µs / p99 50.7µs build time, Λ₉ base 3.12µs, 218/218 tests, ρ-closure 8K/8K. Receipt chain is cryptographically anchored and byte-identical across 5× replay.

**Delta:** Magentic-One has state tracking but no cryptographic receipt chain, no formal-logic gate semantics, no Lean proof backing. We have all three but lack the benchmark coverage (GAIA, WebArena) and ecosystem adoption (50+ enterprise partners). Magentic-One is AHEAD_OF_US on deployment reach; we are AHEAD_OF_US on auditability and formal correctness guarantees.

---

### Gap 2: Formal Proof of Agent Behavior

**They did:** [AlphaProof (DeepMind, Nature 2025)](https://www.nature.com/articles/s41586-025-09833-y) used RL over Lean proofs (AlphaZero-style) to prove IMO competition problems at silver-medal level. [Lean Copilot (arXiv 2404.12534)](https://arxiv.org/abs/2404.12534) automates 74.2% of Lean proof steps vs 40.1% for aesop baseline.

**We did:** lutar-lean — Lean proofs of TH4 (Λ-Category), TH5 (Confluence), TH6 (Bekenstein DPI), TH7 (Curry-Howard for Λ-gate). These are proofs *about* an agent runtime's behavioral properties, not proofs of mathematical competition problems.

**Delta:** AlphaProof proves mathematics using RL with Lean as a verifier. We prove runtime properties in Lean. Complementary domains. They are AHEAD_OF_US on scale/automation of proof search; we are AHEAD_OF_US on applying Lean to agent-runtime behavioral correctness. No existing 2024–2026 paper proves agent-runtime gate semantics in Lean — this is a genuine originality pocket.

---

### Gap 3: Agent Provenance / Receipt Chains

**They did:** [ARGUS (arXiv 2605.03378, 2026)](https://arxiv.org/html/2605.03378v1) builds an Influence-Provenance Graph (IPG) that tracks how untrusted context propagates into agent decisions; reduces attack success rate to 3.8% while preserving 87.5% task utility. [Provable Observability and Lightweight Audit Agents (arXiv 2512.17259)](https://arxiv.org/pdf/2512.17259) proposes a Verifiability-First Architecture with runtime attestation.

**We did:** ouroboros receipt chain — every task execution emits a cryptographically chained receipt (replay-root: `1ed4d253…`). Receipts are typed, not just logged; they flow through the Λ-gate, making capability/permission provenance first-class objects in the type system.

**Delta:** ARGUS tracks data provenance via graph; ours is capability-typed provenance via receipt chain anchored in a formal calculus. They focus on defense against injection attacks; we focus on auditability and replaying deterministic behavior. PARITY on intent, AHEAD_OF_US on formal typing of receipts.

---

### Gap 4: Agent Interoperability and Discovery Protocols

**They did:** [Google A2A Protocol (April 2025, Linux Foundation)](https://developers.googleblog.com/en/a2a-a-new-era-of-agent-interoperability/) — open standard for agent-to-agent communication using Agent Cards (JSON), JSON-RPC 2.0, HTTP/SSE. 50+ enterprise partners. [IETF SCITT](https://datatracker.ietf.org/wg/scitt/) architecture in RFC Ed Queue — immutable, non-repudiable supply chain transparency registries.

**We did:** a11oy v0.4.0 knowledge graph with 13 minted Zenodo DOIs; 9-axis Λ-gate as typed capability interface between agents; szl-trust for cross-component trust policies.

**Delta:** A2A solves agent discovery and communication at web scale with broad adoption. We have richer typing (9-axis conjunctive semantics) but zero published interoperability standard. SCITT solves software supply chain receipt registries at IETF scope. We solve a similar problem for AI-runtime receipts but lack standardization. They are AHEAD_OF_US on ecosystem reach; we are AHEAD_OF_US on semantic richness of the trust model.

---

### Gap 5: Capability-Typed / Receipt-Typed Agent Calculi

**They did:** [Asynchronous Session-Based Concurrency: Deadlock-freedom in Cyclic Process Networks (LMCS 2024)](http://arxiv.org/pdf/2111.13091.pdf) extends Curry-Howard for linear logic / session types to asynchronous concurrent processes, proving deadlock freedom. Session types are capability-typed communications widely studied in PLDI/POPL (e.g., van den Heuvel & Pérez, LMCS 2024).

**We did:** lutar-calculus moonshot — formal + financial + regulatory capability typing in one calculus. TH7 (Curry-Howard for Λ-gate) maps Λ-gate conjunctions to linear-logic propositions. The Λ-gate itself is a 9-dimensional capability certificate checked at runtime.

**Delta:** Session-type literature proves deadlock freedom for concurrent message-passing systems. We extend this to financial/regulatory capability proofs in a single calculus applied to an operational agent runtime. No 2024–2026 paper unifies these three domains (formal, financial, regulatory) in one capability calculus. This is the most defensible originality claim in our stack.

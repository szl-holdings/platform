### P2-D: Adopt Consistent Soft-Delete Pattern (🟡 REVIEW)

**Target:** Standardize on `deleted_at TIMESTAMPTZ DEFAULT NULL` for all mutable domain tables.

**Phase 2D-1 (safe — additive only):**
Add `deleted_at TIMESTAMPTZ DEFAULT NULL` to:
- `vessels`, `vessels_fleets`, `vessels_alert_rules`, `vessels_cargo`, `vessels_routes`
- `firestorm_assessments`, `firestorm_findings`, `firestorm_incidents`, `firestorm_alerts`
- `pc_matters`, `pc_parties`, `pc_claims`
- `terra_deals`, `terra_leads`

Add partial index `WHERE deleted_at IS NULL` on each.

**Phase 2D-2 (requires human approval — behavior change):**
- Backfill: rows with `is_active = false` → set `deleted_at = updated_at` or `now()`
- Update application queries to filter `WHERE deleted_at IS NULL` instead of `WHERE is_active = true`
- Drop `is_active` column (single source of truth)

## Phase 3 — Long-Term Consolidation (Leadership Approval Required)

### P3-A: Unify Multi-Tenancy Model (🔴 GATE)

**Problem:** Two incompatible tenant scope models (`org_id: integer` vs `tenant_id: text`) cannot be joined without an application-layer mapping.

**Proposal:**
1. Create a canonical `tenants` table (separate from `organizations`) that bridges both models.
2. Each `organization` maps to exactly one `tenant`.
3. New tables use `tenant_id → tenants.id` (integer FK).
4. Existing `tenant_id TEXT` columns are backed by a lookup to `tenants.external_id`.
5. Gradually migrate old `org_id` columns to `tenant_id`.

This is a multi-sprint effort. No migration can be written until the data model is agreed upon by Engineering leadership.

---

### P3-B: Unify Audit Trail (🔴 GATE)

**Problem:** Five parallel audit systems, plus JSONB embedded audit trails, create a fragmented audit story.

**Proposal:**
1. Extend `alloy_audit_log` with `domain TEXT`, `tenant_id INTEGER`, `session_id TEXT`.
2. Rename to `platform_audit_log` to remove the Alloy-specific connotation.
3. Deprecate `audit_logs` (migrate existing rows, then drop — requires data migration plan).
4. Deprecate `pc_audit_events` (migrate rows, drop).
5. Replace JSONB `audit_trail` columns in Firestorm tables with FK to `platform_audit_log`.
6. Firestorm-specific audit tables (`firestorm_tool_audit_log`, `firestorm_tradecraft_validation_audit`) remain as domain-specific extensions but write summary rows to `platform_audit_log`.

---

### P3-C: Consolidate Prism Counsel Domain (🔴 GATE)

**Problem:** 13 schema files with overlapping table definitions, incompatible PK types, and duplicated matter structure.

**Proposal:**
1. Add `module TEXT` and `jurisdiction TEXT` discriminator columns to `pc_matters`.
2. Migrate `pc_gc_matters` rows into `pc_matters` with `module='gc'`.
3. Extend `pc_matters` with GC-specific nullable columns (or use a `pc_matter_extensions JSONB` column for module-specific data).
4. Gradually consolidate other `prism_counsel_*.ts` tables into `pc_matters` + child tables.

This requires sign-off from the Prism Counsel product team.

---

### P3-D: Unify Role System (🔴 GATE)

**Problem:** Seven parallel role representations (see schema-audit.md §4.2).

**Proposal:**
1. Make `CanonicalRole` the single source of truth.
2. DB stores only `platform_role` (the canonical enum) on `users`.
3. Deprecate and drop the `roles` + `user_roles` tables (content-based access control moves to `org_members.role`).
4. Deprecate `organization_memberships.role` (merged with `org_members.role` via P2-A).
5. `SzlRole` in `szl_canonical.ts` becomes a type alias for `CanonicalRole`.

# Trust as GTM

**Last updated:** April 2026
**Purpose:** Define how trust becomes a go-to-market asset, not a compliance checkbox

---

## The Vanta/Chainguard Playbook

### Vanta's Trust Center as Sales Tool
Vanta transformed compliance from a cost center into a sales accelerator:
- Trust center is the first thing prospects see (often before the product)
- Self-serve access eliminates security questionnaire bottleneck
- Compliance badges reduce sales cycle friction (SOC 2, ISO 27001, HIPAA)
- NDA-gated sharing for sensitive artifacts accelerates enterprise deals
- Trust center analytics show which prospects are most engaged

### Chainguard's Trust as Differentiation
Chainguard made supply chain security the product, not a feature:
- "Zero known CVEs" is the headline metric — not uptime or performance
- Transparency logs for build provenance (SBOMs, attestations)
- Every container image is provably secure
- Trust positioning attracts security-conscious enterprise buyers who self-select

### Drata's Automation as Trust Evidence
Drata automates evidence collection to prove trust continuously:
- 350+ automated controls across 14+ frameworks
- Real-time compliance monitoring (not annual audits)
- Evidence is always current — prospects see live status, not stale reports

## SZL's Trust GTM Strategy

### 1. Proof Chain as Trust Headline
SZL's equivalent of Chainguard's "zero CVEs" is: **"Every AI decision is provably governed."**

| Trust Claim | Proof Mechanism |
|-------------|----------------|
| "Every recommendation has source attribution" | Proof Chain records model ID, provider, input sources |
| "Every decision has approval governance" | Covenant Policy decisions logged with matched policies |
| "Every outcome is quantitatively tracked" | Outcome Graph records predicted vs. actual with variance |
| "Every action has immutable audit trail" | Decision and action receipts with SHA-256 hashes |

### 2. Trust Center as First Impression
The SZL flagship trust page (`/trust`) should be accessible without login and show:

| Artifact | Status | Auto-Updated |
|----------|--------|-------------|
| Platform security posture | Live indicators | Yes |
| Encryption standards (AES-256-GCM, TLS 1.3) | Static | No |
| RBAC and access control matrix | Reference link | No |
| API security standards | Reference link | No |
| Open-source governance primitives | GitHub links | Yes (commit activity) |
| Compliance roadmap (SOC 2 Type II target) | Timeline | No |

### 3. Open-Source Governance as Trust Signal
Publishing governance primitive source code on GitHub:
- Proves the architecture is real (not marketing)
- Allows technical buyers to audit the implementation
- Attracts developer community contributions
- Positions SZL as a thought leader in governed AI

### 4. Decision Receipt Export as Enterprise Enabler
Enterprise buyers need exportable proof for their own compliance:
- PDF export of decision receipt chains
- JSON export for integration with buyer's SIEM/compliance tools
- Structured format compatible with common GRC frameworks

## Competitive Advantage Summary

| Company | Trust Approach | Limitation |
|---------|---------------|-----------|
| Vanta | Prove you follow rules | Only covers compliance frameworks |
| Drata | Automate evidence collection | Only covers infrastructure controls |
| Chainguard | Prove software supply chain | Only covers container images |
| SZL | Prove every decision is governed | Covers AI recommendations, human decisions, and outcomes |

SZL's trust surface is broader: it covers the *decision* layer, not just the *infrastructure* layer. This is a structural advantage in the AI governance market.

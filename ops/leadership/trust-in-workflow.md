# Trust in Workflow

**Owner:** Stephen Lutar · **Audience:** Founder, design, compliance buyers

Trust is not a page. Trust is a property of every screen. If a buyer has to navigate to a "trust center" to find evidence, governance, or audit, we have already lost the argument.

This document defines how trust shows up *in* the workflow — as native UI, not as a bolt-on.

## The five trust signals

### 1. Provenance pill
**Where:** Every signal, recommendation, action, and audit row.
**Looks like:** A small monospace pill carrying the source system identifier and a confidence value where applicable.
**Example:** `salesforce / opp #ENT-7721 · 0.95` on a value-at-risk evidence row.
**Rule:** No data point appears without a provenance pill or an explicit "no source" tag. Silent fallbacks are forbidden.

### 2. Evidence rows
**Where:** Decision receipts and action cards.
**Looks like:** Labelled rows with a value, a source, and an optional confidence.
**Example:** `Queue Dwell Time · 48h 12m · workflow-engine / approval-svc · 0.98`.
**Rule:** A recommendation with fewer than three evidence rows is flagged as "low evidence" — the UI itself surfaces the weakness instead of hiding it.

### 3. Approval chain affordance
**Where:** Anywhere a policy gate applies.
**Looks like:** A horizontal chain of pills showing tier, named approver, SLA, and current state.
**Rule:** The chain is always visible — collapsed when complete, expanded when in flight. The override path is a button on the chain, never a hidden setting.

### 4. Audit trail indicator
**Where:** Top-right of every operator surface that mutates state.
**Looks like:** A small Shield icon with a count of audit events generated by the current view in the last hour.
**Rule:** Clicking the indicator opens the trust audit filtered to the current resource. Audit is one click from anywhere.

### 5. Demo / production tag
**Where:** Persistent in the layout chrome.
**Looks like:** A pill in the top bar reading either `DEMO DATA — SEEDED` (amber) or `PRODUCTION` (green).
**Rule:** The tag is non-dismissible. Demo data must never appear without the demo tag visible. This is a core safety contract, not a UX preference.

## Where trust must be loud

- **Signal sources** — visible on the row, not behind a click.
- **Recommendation scoring factors** — top three always visible, full set behind expand.
- **Override paths** — always one click, always logged with attribution.
- **Audit outcomes** — colored chips (success / denied / warning), not buried text.

## Where trust must be quiet

- **Background telemetry, deltas, and refresh ticks** — these should pulse, not shout.
- **Confidence values below 0.5** — render with reduced opacity, but still render. Buyers should know the model knows.
- **System actors** — present as `actorType: "agent"` or `actorType: "system"`, never anthropomorphized.

## What trust is not

- Trust is not a banner that says "we are SOC 2." Compliance certifications belong on the marketing site; in product they belong in the audit log as policy attestations.
- Trust is not a modal asking for confirmation. Modals are friction, not trust. Trust is *traceability after the fact*.
- Trust is not a separate tab. The minute trust lives in its own tab, it stops being part of the workflow.

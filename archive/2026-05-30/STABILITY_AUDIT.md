**File:** `artifacts/szl-holdings/src/data/capability-manifest.json`

The broken symlink was replaced with a valid JSON stub that has an empty `capabilities` array. The following dashboard pages now build and render without crashing, but display no capability data:

- `src/pages/product-readiness.tsx`
- `src/pages/trust-status.tsx`
- `src/pages/trust-center.tsx`
- `src/pages/changelog-highlights.tsx`
- `src/pages/investors-overview-v2.tsx`

**Product decision needed:** Who owns populating this manifest, and what is the canonical source? The original symlink pointed to `artifacts/audit/platform-capability-manifest.json`, which does not exist. Options:
- Generate it from an automated audit script and commit the output
- Maintain it as a hand-curated file alongside the dashboard
- Pull it from an API at runtime and remove the static import

Each capability entry requires: `id`, `product`, `capability_name`, `claim_source`, `route_or_module`, `status`, `evidence`, `test_coverage`, `blocking_dependencies`, `owner`, `severity`. See `src/hooks/useCapabilityManifest.ts` for the full TypeScript type.

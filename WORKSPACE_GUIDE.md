# Workspace Guide — SZL Holdings Platform

> Internal reference for developers, operators, and authorized collaborators working in the SZL Holdings Replit workspace.

---

## What This Workspace Is

This is the active development and operations workspace for the **SZL Holdings platform ecosystem**. It is a pnpm monorepo containing all web apps, mobile apps, the shared API server, component libraries, and infrastructure configuration.

The workspace runs on Replit and is the primary source of truth during active development. Azure production deployments are provisioned separately from the `/infra/` directory.

## What Is Public vs. Private

### Public Routes (safe to show externally)
- `szl-holdings` marketing pages: `/`, `/platform`, `/lyte`, `/alloy-fabric`, `/solutions/*`, `/trust-center`, `/pricing`, `/contact`, `/design-partners`, `/status`, `/legal/*`, `/docs/*`
- `carlota-jo`: all public client-facing pages
- `stephen-site`: personal site / personal brand

### Internal / Demo-Only Routes (NOT for external sharing without context)
- `/admin` — internal CMS admin (PIN-gated)
- `/ops/*` — internal ops dashboard (internal only)
- `/alloy/*` — Alloy workflow engine app (demo only)
- `/prism-counsel/*` — PRISM Counsel law tech app (demo only)
- `/kpi-dashboard` — internal KPI tracking
- `/investors/*` — investor data room (private)
- All Expo mobile apps — demo only, not yet publicly distributed

### Staging / Development Only
- `/__mockup` — component preview sandbox, never expose externally
- `/azure-tenant-*` — enterprise tenant onboarding (internal preview)
- `/s31/*`, `/s32/*`, `/ny/*` — feature sprint routes, internal only

## How to Run Locally

Each artifact is a separate pnpm workspace package. All workflows are managed by Replit.

**Start all services:** Use the Replit workflow manager (each artifact has its own workflow).

**Start individual artifact:**
```bash
pnpm --filter artifacts/szl-holdings dev
pnpm --filter artifacts/api-server dev
```

**Build all:**
```bash
pnpm build
```

**Typecheck:**
```bash
pnpm typecheck
```

**Lint:**
```bash
pnpm lint
```

## How to Deploy

See [DEPLOYMENT_READINESS.md](DEPLOYMENT_READINESS.md) and [RELEASE_PROCESS.md](RELEASE_PROCESS.md) for the full workflow.

**Summary:**
1. Run pre-release checklist from [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md)
2. Deploy API server first (database migrations first, then server restart)
3. Deploy web artifacts to Azure App Service
4. Verify health checks on all critical routes
5. Update CHANGELOG.md and tag the release

**Infrastructure:** Azure Bicep templates in `/infra/`. See `/infra/README.md`.

## Where Screenshots Come From

Screenshots are generated by `scripts/media/capture-screenshots.sh`. They are stored in `docs/media/screenshots/`. See [DEMO_GUIDE.md](DEMO_GUIDE.md) for what to capture and when to refresh.

To regenerate screenshots:
```bash
pnpm capture:screens
```

---

## How Demo Data Works

Demo data is seeded via scripts in `scripts/`:
- `scripts/seed-demo-data.ts` — primary demo seed
- `scripts/seed-demo-canonical.sh` — canonical demo org setup
- `scripts/seed-pilot-data.ts` — pilot org seed

To reset and reseed:
```bash
pnpm seed:demo
```

Demo data is **never** used in production. The database environment is isolated per deployment environment.
